# 🚀 Evergreen Research — Launch Runbook

Everything the machine cannot do for itself, in order of leverage.
Tick items off as you go; the automated side (corpus, verification,
audit, snapshots) already runs itself.

## 1. Publish the repo (30 min)

```bash
gh auth login -h github.com          # interactive, pick HTTPS
cd evergreen-research
gh repo create evergreen-research --public --source=. --push
```

Then in repo settings:

- **Pages**: Settings → Pages → Source: `Deploy from a branch` → branch
  `main` / folder `/docs` → Save. Landing page: `docs/index.md`.
- **Actions**: the weekly cron (`weekly.yml`) needs no extra permissions
  (it requests `contents: write` itself). Watch the first manual run:
  Actions → weekly-research → Run workflow.
- **Topics**: add `arxiv`, `deep-research`, `research-intelligence`,
  `survey`, `frontier-ai`.

## 2. Citation tracking at full rate (10 min)

1. Register at <https://semanticscholar.org> → API key (free).
2. `export S2_API_KEY=...` (and set it as an Actions secret if you want
   the cron to batch citations).
3. `python3 -m evergreen.cli citations --top 45` and re-run weekly to
   see `data/citations.jsonl` fill.

## 3. Human review gate (the real work)

The GO/NO-GO gate requires **≥2 humans who are not the tooling** to read
the draft end-to-end.

- [ ] Reviewer 1: **you**. Read `data/survey/draft.pdf` (12 pages).
  Mark anything overclaimed, unclear, or unsupported.
- [ ] Reviewer 2: someone who knows LLM reasoning (a researcher, a
  senior engineer, a quant colleague). Ask for 1 hour, offer co-authorship
  if they contribute meaningfully.

Reviewer checklist (from `data/survey/positioning.md`):

1. Is every bold claim traceable to a corpus record?
2. Do §5's convergence tables overreach the abstract-level caveat?
3. Does §6's benchmark-visibility claim survive scrutiny?
4. Is the "living survey" framing credible, or does it read as marketing?
5. Would you sign your name to the open-problems list?

## 4. Endorsement (the arXiv hard gate)

`cs.AI` / `cs.LG` / `cs.CL` require endorsement for first-time authors.
Options, best first:

1. **Co-author who is established** in any of those categories.
2. **Endorsement request** to someone you know (template below).
3. **Fallback venue**: keep the repo/digests as the publication artifact;
   submit to a journal or workshop that reviews unaffiliated authors.

Template (keep it short, specific, and easy to say yes to):

> Subject: Endorsement request for an arXiv submission
>
> Hi [Name],
>
> I built an open-source research pipeline that weekly ingests and verifies
> frontier AI papers (github.com/evergreen-research) and wrote a survey from
> its corpus — "The Compute-Allocation Frontier" (12-page draft attached).
> Submitting to [cs.AI] requires an endorsement from an established author.
> Would you be willing to skim the draft and, if it meets the bar, endorse
> it? Happy to make any changes you suggest first.
>
> Thanks,
> [You]

## 5. arXiv submission checklist

- [ ] Account at arxiv.org (new accounts need moderator approval; do it now,
      it takes days).
- [ ] Category: `cs.AI` (primary) — or `cs.LG` if the reviewer suggests.
- [ ] License: **CC BY 4.0** (matches the repo's data license).
- [ ] Files: `data/survey/arxiv/main.tex` compiles clean (verified locally:
      12 pages, 0 errors). Our citations are plain `\href`/text, so no
      `.bbl` is required.
- [ ] Metadata: title, abstract (in `main.tex`), authors, comments field:
      "Generated by the Evergreen Research corpus pipeline; data at
      github.com/evergreen-research".
- [ ] Submit → expect announcement in 1-2 business days after moderation.

## 6. After announcement

- [ ] Add the arXiv id to `README.md` and `positioning.md`.
- [ ] Upload `data/snapshots/evergreen-data-<date>.tar.gz` + manifest to
      Zenodo (DOI for the data).
- [ ] Announce: repo Discussions, X/Bluesky, r/MachineLearning, HN (with
      the "living survey" angle, not "another survey").
- [ ] Plan the follow-up venue/journal submission (positioning.md §risks).

## 7. Keep the machine honest

- Every Monday the cron runs `weekly → audit → snapshot → rss` and commits.
- If the audit ever reports FAIL, fix the draft before touching anything else.
- `data/survey/audit-report.md` is the public health certificate.

---

*The automated research loop was built to make this list as short as
possible. The rest is reputation, judgment, and a few yes-es.*
